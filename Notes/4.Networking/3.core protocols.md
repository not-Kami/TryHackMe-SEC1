🌐 Networking Core Protocols: Application Layer Services

1. Domain Name System (DNS)

DNS is the Internet's directory service. It translates human-readable domain names (e.g., `google.com`) into IP addresses.

    Port: DNS usually uses UDP `53`. If the response is too large, it can fall back to TCP `53`.

    Essential DNS record types:

        A: Maps a hostname to an IPv4 address.

        AAAA: Maps a hostname to an IPv6 address.

        CNAME: Canonical Name record (alias pointing to another domain name).

        MX: Mail Exchange record (mail servers responsible for a domain).

2. WHOIS

WHOIS is used to query databases for information about domain owners and/or IP blocks.

    Common fields: registrant, creation/expiration dates, and associated DNS/name servers.

    Cyber use: OSINT reconnaissance to identify organizations and infrastructure.

3. HyperText Transfer Protocol (HTTP)

HTTP is the base protocol of the Web. It follows a request/response model.

    Common HTTP methods:

        GET: Request a resource.

        POST: Send data to the server (e.g., a form submission).

        HEAD: Request only headers (no response body).

    Common status codes:

        200 OK: Request succeeded.

        301/302: Redirection.

        403 Forbidden: Access denied.

        404 Not Found: Resource does not exist.

        500 Internal Server Error: Server-side error.

4. HyperText Transfer Protocol Secure (HTTPS)

HTTPS = HTTP carried over TLS (Transport Layer Security).

    Port: TCP `443`.

    Why it matters: confidentiality (encryption) + integrity + server authentication via certificates.

5. Email Protocols (SMTP, POP3, IMAP)

Email delivery and access are handled by different protocols depending on the direction.

Sending: SMTP (Simple Mail Transfer Protocol)

    Purpose: send emails from a client to a mail server, or between mail servers.

    Ports: `25` (standard), `587` (submission, typically with STARTTLS).

Receiving: POP3 vs IMAP

| Characteristic | POP3 (Post Office Protocol v3) | IMAP (Internet Message Access Protocol) |
|---|---|---|
| Philosophy | Downloads and (often) removes mail from the server | Keeps mail on the server; syncs state to clients |
| Usage | Usually single device / offline-oriented | Multi-device syncing (phone + PC) |
| Ports | `110` (insecure), `995` (SSL/TLS) | `143` (insecure), `993` (SSL/TLS) |

6. Telnet-style manual interaction (plaintext testing)

Telnet can be used to manually talk to plaintext services (when supported).

Examples (high level):

    SMTP: connect to port `25`, then use commands like `HELO`, `MAIL FROM`, `RCPT TO`, `DATA`.

    IMAP: older/unencrypted setups may allow plaintext interaction, but in practice you often need TLS.

Important note:

    For encrypted services (HTTPS/TLS, SSH, and most modern email), Telnet is not the right tool. Use an SSH client or a TLS-capable client instead (e.g., `openssl s_client`).

7. Secure Shell (SSH)

SSH provides secure remote access and command execution.

    Port: TCP `22`.

    Authentication: passwords or (preferably) public/private key pairs.

    Common use: administration, secure tunneling/port forwarding, and remote scripting.

8. File Transfer Protocol (FTP) and SFTP

FTP transfers files, typically with separate control/data channels.

    FTP: control on TCP `21` (data differs by active/passive mode).

    SFTP: file transfer over SSH (often TCP `22`), easier to traverse and generally safer than classic FTP.

9. SMB / CIFS (file sharing)

SMB is widely used for shared files/printers in Windows environments.

    Ports: TCP `445` (SMB over direct TCP).

    (Historically: NetBIOS over TCP `139` is also relevant in some setups.)

10. Network Time Protocol (NTP)

NTP keeps system clocks synchronized (important for logs, authentication, and time-based security systems).

    Port: UDP `123`.

Summary for your repository notes

    DNS: name resolution (port `53`).

    HTTP: web navigation (port `80`).

    HTTPS: web over TLS (port `443`).

    SMTP: email sending (port `25`).

    IMAP/POP3: email receiving (ports `143` / `110`).

    SSH: secure remote access (port `22`).

    FTP: file transfer control (port `21`).

    SMB: Windows file sharing (port `445`).

    NTP: time synchronization (port `123`).
